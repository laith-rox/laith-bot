# بوت ليث — إشارات الذهب 2.0

بوت مستقل لـ XAU/USD يرسل تنبيهات تحليلية إلى `@LaithGoldSignalsBot`، ويتابع مستوياتها. المشروع الأصلي `xau-signal-bot` منفصل تمامًا.

## السلوك الحالي

- جلب شموع 5 دقائق من Twelve Data، بطلب واحد كل 5 دقائق افتراضيًا وبتوقيت UTC صريح. طلب 2400 شمعة يوفر تاريخًا أطول لمتوسطات الساعة؛ الإشارات تحتاج 220 شمعة 15د و100 شمعة ساعة مغلقة على الأقل.
- رفض القيم غير المنطقية، التوقيت المستقبلي، التكرارات المتضاربة والبيانات القديمة. ترتيب البيانات وتوحيد توقيتها؛ إسقاط الشموع غير المغلقة والمجموعات الناقصة عند بناء 15د و1س.
- اتجاه EMA20/50 على 15د و1س، RSI وMACD وATR. لا يمكن تجاوز فلتر RSI أو بُعد السعر عن المتوسط بمجموع النقاط. تحقق الشروط ليس احتمال نجاح.
- ساعات إشارات الدخول: الاثنين–الجمعة، 04:30 حتى ما قبل 23:30 بتوقيت `Asia/Hebron`. هذه ساعات المستخدم، وليست تقويم عطلات وسيط محدد. متابعة الإشارة القائمة تستمر خارج هذه الساعات.
- إشارة واحدة قيد المتابعة؛ تقييم دخول واحد لكل شمعة 15د، وفاصل 60 دقيقة على الأقل بعد الإرسال المؤكد. صلاحية رسالة الدخول غير المرسلة دقيقتان.
- حماية دخول قبل أخبار USD عالية التأثير بـ30 دقيقة وبعدها بـ15 دقيقة. المصدر هو جدول Fair Economy الأسبوعي، يُحدّث كل ساعة ويُرفض إذا تجاوز ساعتين أو انتمى لأسبوع آخر. تعذّر الحصول على جدول صالح يمنع إشارات جديدة ويُبقي متابعة الإشارة الحالية.
- وقف أول 1.4 ATR، هدف أول 1.8 ATR وهدف ثانٍ 2.6 ATR. رصد الهدف الأول يولّد اقتراح نقل الوقف إلى الدخول، ويُفعّل نموذج المتابعة هذا المستوى من الشمعة التالية؛ لا ينقل البوت أي أمر عند وسيط.
- إذا لمست شمعة الوقف والهدف ولم يُعرف الترتيب، تُسجّل النتيجة غير محسومة. الفجوات في البيانات والإرسال غير المؤكد تستبعد النتيجة من إحصاءات الأداء.
- إيقاف اقتراحات الدخول لبقية اليوم عند وصول سجل النموذج إلى -3R. كل نتيجة غير قابلة للقياس تحتسب -1R لهذا الحاجز فقط، ولا تُعرض كخسارة مؤكدة في الإحصاءات. يعود الحاجز اليومي تلقائيًا في اليوم التالي بتوقيت فلسطين؛ الإيقاف اليدوي يبقى حتى `/resume`.
- مراجعة كل ساعة للإشارة القائمة باستخدام النموذج نفسه، وأوامر للمستخدم صاحب المحادثة الخاصة فقط.

## أوامر Telegram

| الأمر | وظيفته |
|---|---|
| `/status` | حالة البيانات، سبب الانتظار والإشارة الحالية |
| `/stats` | نتائج المتابعة وأكبر تراجع بوحدة R |
| `/pause` | إيقاف دخول جديد وإلغاء الرسائل غير المرسلة، مع استمرار متابعة الإشارة القائمة |
| `/resume` | رفع الإيقاف اليدوي مع بقاء حواجز البيانات والأخبار والمخاطر |
| `/help` | قائمة الأوامر |

يتحقق التشغيل من اسم البوت قبل إرسال أي شيء. إذا وجد webhook قائمًا، لا يغيّره؛ يعطّل سحب الأوامر في هذه النسخة فقط ويسجّل ذلك. لا تنشر أكثر من worker واحد.

## الحفظ والإرسال

SQLite على Volume دائم عند `/data/laith.sqlite3`، مع معاملات وتسجيل WAL وقفل عملية واحدة. تُحفظ الإشارات وطابور الرسائل والأوامر وتقويم الأخبار. القرارات تبقى 90 يومًا والشموع 180 يومًا؛ نتائج الإشارات تبقى محفوظة.

السجل والمتابعة يبدآن بالإشارات الجديدة بعد التحديث. الإصدار القديم لم يحفظ سجل صفقاته، لذلك لا تُفترض استعادة إشاراته السابقة أو معرفة صفقات حساب الوسيط.

لا تبدأ مهلة التكرار إلا بعد إقرار Telegram بالنجاح ورقم الرسالة والوجهة الصحيحة. الرفض المؤكد المؤقت يُعاد بانتظار متزايد وحد أقصى 5 محاولات، مع احترام `retry_after`. فشل الاتصال قبل الإرسال قابل للمحاولة؛ انقطاع الرد أو انهيار العملية أثناء الإرسال يترك الوصول غير مؤكد. عندها لا تُرسل رسالة الدخول تلقائيًا مرة ثانية، وتُعلّق الإشارات الجديدة ويظهر السبب في `/status`. تحقّق من الرسالة قبل `/resume`.

المساحة المطلوبة صغيرة: Volume واحد 512MB. أسعار Railway تعتمد على استخدام الحساب؛ راجع [وثائق التخزين](https://docs.railway.com/volumes) و[الأسعار](https://railway.com/pricing). لا توجد خدمة قاعدة بيانات إضافية أو اشتراك ذكاء اصطناعي في هذه النسخة.

## الإعداد

| المتغير | الاستخدام |
|---|---|
| `TELEGRAM_BOT_TOKEN` | مفتاح البوت الجديد فقط؛ لا يوضع في GitHub |
| `TELEGRAM_CHAT_ID` | المحادثة الخاصة بصاحب البوت |
| `TWELVE_DATA_API_KEY` | مفتاح مصدر البيانات |
| `EXPECTED_BOT_USERNAME` | افتراضيًا `LaithGoldSignalsBot`؛ يمنع استخدام بوت آخر بالخطأ |
| `CHECK_INTERVAL_SECONDS` | افتراضيًا 300، وبحد أدنى 300 |
| `SIGNAL_COOLDOWN_MINUTES` | افتراضيًا 60، وبحد أدنى 60 |
| `SYMBOL` | يجب أن يكون `XAU/USD` |
| `STATE_DIR` | اختياري؛ يجب أن يكون داخل Volume على Railway |

Railway يوفّر `RAILWAY_VOLUME_MOUNT_PATH` تلقائيًا. يرفض البرنامج تشغيل الخدمة هناك دون حفظ دائم. أمر التشغيل `python bot.py`. ملف `.python-version` يحدد Python 3.12.

```sh
python -m pip install -r requirements.txt
python -m unittest -q test_bot
python bot.py --once
```

الأمر الأخير يقرأ السوق فقط ويحتاج مفتاح Twelve Data؛ لا يرسل Telegram. الاختبارات تستخدم بيانات مصطنعة ونقلًا وهميًا، ولا تتصل بالسوق أو ترسل رسائل. لا تستخدم `python bot.py` لاختبار محلي مع مفاتيح خدمة تعمل بالفعل.

## الاختبار التاريخي

```sh
python bot.py --export-csv candles.csv
python backtest.py candles.csv --spread 0.40 --slippage 0.10
```

القيم أعلاه أمثلة وليست تكاليف وسيطك. Spread تكلفة الدورة الكاملة بوحدات سعر الذهب، والانزلاق لكل جهة. يمكن تحديد `--holdout-from 2026-09-01` لفصل فترة قياس عن بيانات التهيئة، و`--events-json events.json` لتطبيق قائمة تاريخية من أخبار USD العالية بصيغة `[{"time": 1789030800, "title": "Example"}]`. الأرقام في هذا المثال توضيحية فقط.

المحاكاة تتحرك للأمام، وتنتظر أول افتتاح شمعة 5د كاملة بعد وقت اتخاذ القرار للدخول؛ لا تدخل بسعر افتتاح سبق القرار. لا تستعمل شموعًا مستقبلية في المؤشرات. أسعار الدخول والملء افتراضية، وتختلف عن اقتراحات البث المباشر، والتكلفة ثابتة مفترضة؛ لذلك ليست نسخة مطابقة لتنفيذ حساب وسيط. الصفقات المفتوحة في نهاية العينة لا تُغلق اصطناعيًا لرفع النتائج. عند عدم تقديم تقويم تاريخي، يظهر `NOT_SIMULATED` لحماية الأخبار. اكتمال هذا التقويم غير متحقق آليًا.

## حدود القياس

المتابعة تعتمد على شموع 5د وليست تيكات وسيطك. الشمعة التي تتقاطع مع وقت وصول الدخول تُستخدم إغلاقتها فقط، لتجنّب احتساب لمسات قبل الإعلان؛ قد تفوت لمسات حدثت داخل هذه الشمعة. بعد ذلك تُستخدم القمم والقيعان ويُسجّل غموض ترتيب اللمسات. الحماية عند الدخول افتراضية من الشمعة التالية حتى لو تعذّر وصول تنبيه الحماية؛ على المستخدم إدارة وقف الوسيط مباشرة.

إحصاءات `/stats` قبل السبريد والرسوم، وR مسافة سعرية بين الدخول والوقف الأول، وليست ربح الحساب أو نسبة نجاح متوقعة. الأخبار المفاجئة ليست مغطاة بجدول المواعيد. لم يُثبت هذا الإصدار ربحيةً باختبار تاريخي مستقل أو متابعة طويلة؛ تحسين الاعتمادية لا يثبت الربح.

## التشغيل والأعطال

سجل الخدمة يظهر إصدار البرنامج، تحقق اسم البوت، حالة الحفظ، أسباب الانتظار ومعرّفات رسائل Telegram الناجحة. تُخفى المفاتيح وروابط الأخطاء الحساسة. `market_quota_reached` يعني انتظار تجدد حصة المصدر؛ `calendar_unavailable` يمنع الدخول حتى توفر تقويم صالح؛ `persistent_volume_required` يتطلب تفعيل الـVolume على الخدمة الجديدة.

المفتاح الذي ظهر في سجلات الإصدار القديم لا يمكن إخفاؤه بأثر رجعي بتعديل الكود؛ استبداله يتم من حساب مصدر البيانات، مع مراعاة أي خدمات أخرى تستخدمه. هذا الإصدار لا يعدّل مفاتيح خدمات أخرى.
